# 验证范围

记录日期：2026-10-26。

## 已有原生客户端实测

本公开版来自已经在 Windows `OpenAI.Codex` 原生宠物窗口使用的运行时实现。已对 `26.1021.3705.0` 安装包做过以下实测：

- 用户实际双击：炸盆后戴盆，再双击恢复普通。
- 用户实际悬停：普通和戴盆形态各哈一次，结束恢复当前动作，移开再进入可重播。
- Running 持续循环吃饭，并观察到工作结束回 Idle。
- 戴盆时走左、走右和跳跃保持头盆；所有非烘焙帧的锚点另有逻辑覆盖。
- 完整客户端重启，进入新 renderer 后恢复戴盆。
- 原程序 EXE/ASAR 哈希在集成前后相同，程序签名有效。
- 原开始菜单图标和名称保留；停用恢复、重新启用仍保留形态。
- 无窗口宿主的备用入口和日常入口均实际启动；桌面窗口检查无终端残留。

没有为拍摄/验收故意制造真实失败任务；Failed 槽是按原 V1 帧逐像素恢复和时序校验。没有承诺其他客户端版本完全兼容。

## 本公开版本的验证

公开版把账号相关 ID、本机路径、运行状态与源码分离，不包含原用户的安装清单、日志或程序副本。

- 11 项原有纯逻辑测试覆盖变身最终帧提交、过期回调、连续动作戴盆、双击过滤、悬停消费与恢复。
- 新增配置边界、独立存储命名空间、序列化注入语法测试。
- 五个图集使用 SHA-256 清单校验。
- PowerShell 脚本执行语法分析。
- GUI 宿主从公开源码构建，检查 PE 子系统确实为 Windows GUI。
- GitHub CI 在干净 Windows/Linux 环境运行逻辑与素材验证，在 Windows 构建宿主。

原生人工验收来自本机集成版本；不能把它等同于对每个读者账号、Windows 策略和客户端版本的重新安装验收。公开安装器遵循同一机制，但不同环境仍需按快速开始和验收步骤验证。

## 手动验收步骤

1. 普通形态 Running：至少观察三轮连续吃饭。
2. 鼠标移入停住：只哈一次，恢复吃饭；移开再进入可重播。
3. 双击：完整播放炸盆，最后一帧后才切到戴盆。
4. 戴盆形态重复步骤 1、2，并拖动验证头盆仍在。
5. 保持戴盆，正常退出并从桥接入口重启，确认恢复。
6. 停用后原精灵恢复，原入口恢复；再启动后形态保留。
7. 确认没有第二个桌面宠物和常驻终端窗口。

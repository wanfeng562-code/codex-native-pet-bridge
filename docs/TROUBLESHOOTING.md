# 排障

## 没有找到原生宠物窗口

确认使用桥接入口启动了原客户端，并且客户端里已选择、显示原生宠物。查看 `node bridge/controller.mjs status`；`waiting-for-native-client` 表示后台在等待，不代表需要复制客户端。`tools/inspect-pet.mjs` 只在一个可见宠物 renderer 存在时返回 ID。

## 客户端已经打开但连接未启用

Electron 的调试参数通常需要在应用启动时传入。保存工作并完整退出后，从 `Start Codex Pet.lnk` 启动。直接点旧的任务栏固定应用可能绕过桥接；本项目默认不会替你关闭正在工作的客户端。

## 能看到宠物，但仍然只有原版动作

检查 `bridge/config.local.json` 的 `petId` 是否与 `inspect-pet.mjs` 一致。桥接只针对匹配 ID 挂载。还要检查图集哈希、端口、是否选了另一个宠物，以及是否同时运行了另一套实验桥接。

## 启动时出现命令行窗口

使用生成的 `.lnk`，其目标应为 `bridge/.runtime/bridge-host.exe`，参数为 `launch`。不要把 PowerShell 脚本、CMD 或 Node 程序本身固定为日常入口。只有 `-WindowStyle Hidden` 不等价于不创建控制台；本项目从 GUI 子系统宿主开始启动进程。

## Running 没吃饭

查看 `status.json` 的 `nativeAction`、`foregroundBusy` 和 `action`。原生状态和实际任务可能短暂不同步，工作补偿信号只检查可见可用的停止控件，不是服务端任务接口。不同语言、客户端控件变更、后台任务或未显示的聊天窗口可能需要调整适配器。

## 悬停反复哈气或哈气后不恢复

检查是否有另一套播放器/桥接同时注入，是否真的离开又进入宠物区域，以及原生 DOM 是否发生不兼容变化。当前版本只有离开矩形后才重新武装；停在透明像素边缘不应重复触发。请在普通、戴盆两种形态下分别验证。

## 重启后没有恢复戴盆

先等炸盆最后一帧完成，再退出。查看 `.runtime/state.json` 中的稳定形态和当前 petId。换了账号、选了另一个宠物、删除了 localStorage 与磁盘备份，都会影响恢复。不要将一个账号的宠物 ID 硬复制给另一个账号。

## 更新后没有动作

客户端可能改变了 `avatar-overlay` URL、容器选择器、动作属性或调试支持。先停用，确认原生图层恢复，再提交不含账号信息的错误摘要。不要上传整个 `.runtime`、用户 profile、聊天数据库或完整调试页面列表。

## 如何减少占用

当前方案只需要仓库源码、五张图集、小型 GUI 宿主和一个 Node 控制器。不要保留旧版完整客户端、ASAR 备份或独立测试 profile 作为运行依赖。停止桥接即可退出其常驻进程；关闭客户端本身不会停止登录后台任务。

`events.jsonl` 是本地追加日志，长时间使用可在停用后清理。删除磁盘旧副本释放的是存储空间；只有结束运行进程才会释放对应 RAM。不要结束与宠物无关的 Node/PowerShell 进程。
